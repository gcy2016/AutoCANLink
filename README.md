# AutoCANLink

一个跑在浏览器里的汽车 CAN / CAN FD 诊断工具：插上 CANable 2.0 适配器就能录报文、看信号、发 UDS 诊断、刷写 ECU。免安装，手机和电脑都能用，录制和配置数据全程留在本机、不上传到任何服务器。

**在线体验（GitHub Pages）：** https://gcy2016.github.io/AutoCANLink/

> 本工具不内置任何车型的数据。控制器、安全算法、刷写流程、诊断问卷、DBC 全部由使用者自己配置或导入——换个车型、换个控制器，改配置就行，不用改代码。

## 功能

- **报文录制**：CAN / CAN FD 帧录制、实时统计、打标记，导出 BLF（Vector 格式，CANoe 可直接打开）/ ASC / CSV；也能打开已有的 BLF / ASC / CSV 回放分析
- **信号查看**：导入 DBC 后实时解码信号、画曲线；录制时可挑帧打标记，回放时按标记跳转
- **UDS 诊断**：多控制器管理（请求 / 响应 / 功能寻址 ID、填充字节、CAN FD 与 BRS 开关都可配）；会话控制、安全访问（算法插件，见下）、读 / 清故障码（对照自己导入的问卷显示含义）、读写 DID、例程控制、常用指令收藏、原始帧收发
- **故障码监听**：盯住指定帧 ID，一旦目标帧出现就显示并语音播报对应的故障码；监听哪些 ID 自己加
- **ECU 刷写**：可编辑的刷写流程（JSON）：进会话、安全访问、写指纹、擦除、下载 Driver / App（S19 / Intel HEX）、校验、复位；指纹里的诊断仪编号优先从 USB 设备序列号或本机标识自动生成
- **离线数据页**：导入诊断问卷（Excel）和 DBC 后离线查故障码含义、解析报文、信号曲线回放
- **演示模式**：不接硬件也能把主要界面点一遍（模拟帧 + 模拟诊断应答）

## 自己配置（没有内置数据）

- **控制器**：诊断页「控制器」卡里新增，名称和 ID 自己填，可建多个、随时改删
- **安全算法**：写成一段 JS 插件（函数体，可用 `seed`、`level`、`req`，返回 key 字节数组），粘贴到对应控制器的「安全算法插件」框里，只记在本机；也可以随配置包统一载入一套全局算法
- **刷写流程**：刷写页内置一个标准 UDS 顺序的通用模板，可直接改 JSON，也可导入 / 导出流程文件
- **问卷 / DBC**：离线数据页里上传自己的 Excel 问卷和 DBC 文件，记在本机优先使用
- **配置包**：把自己的控制器、算法、流程、问卷和 DBC 打成一个加密文件（格式见 `docs/data.js` 注释，PBKDF2-SHA256 + AES-256-GCM），在设置里导入并输密码解锁，换设备时一次带走；密码只在本机，不经过网络

## 使用要求

- 硬件：CANable 2.0（MKS / protofusion 等版本均可），刷入随附的 vdlink 固件（设置页里有刷入入口和步骤；固件源码在 `firmware/`）
- 浏览器：Chrome 或 Edge（Android / Windows / macOS），需要 WebUSB / Web Serial；**不支持 iOS / iPadOS 及 HarmonyOS**
- 打开网页后点「打开通道」选设备即可；网页可离线使用（首次打开后自动缓存），也可添加到手机主屏幕当 App 用

## 安全与隐私

- 不接任何后端：没有账号、没有上报，录制和配置只存在本机浏览器里。唯一的例外是离线数据页的 AI 助手（可选功能）：需要你自备模型厂商的 API Key，你的提问会由浏览器直接发给所选厂商
- 刷写是高风险操作：请确认流程、文件和目标控制器无误，并保持供电稳定；本工具按现状提供，使用者自担风险

## 开发与自测

网页是纯静态文件（`docs/`），无构建步骤，本地起个静态服务器即可。`test/` 里是 Node 自测（协议解析、刷写引擎、文件解析、配置包加解密、网页冒烟）：

```
node test/test_diag.js
node test/test_flash.js
node test/test_flashfile.js
node test/test_dfu.js
node test/test_data.js
node test/test_web.js
```
